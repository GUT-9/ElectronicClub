# 彻底删除成员

新增独立权限 `members.purge`，在「角色与权限 → 账号与安全」配置，可查询拥有该权限的成员并沿用角色分配/撤销。超级管理员默认拥有，迁移不向其他现有角色自动授予；新安装的普通管理员也不会自动得到这项权限。操作界面同时需要 `members.read` 才能打开成员详情。

## 删除范围

先在成员详情执行「软删除成员」，随后页面显示「彻底删除成员」。输入页面显示的该成员学号（已匿名化成员输入 UID）确认，再点击「永久删除，无法恢复」。成功后返回成员列表并显示完成提示。

后端只允许删除已软删除、非当前登录账号、非超级管理员，且没有业务关联的成员。原 RBAC 管理范围仍生效，不能删除权限高于自身的成员。拥有软删除权限不等于拥有彻底删除权限。

以下情况会拒绝删除：存在活动发布/负责人、报名/签到/审核、新闻发布、论坛帖子/评论/点赞/收藏/举报/通知/限制记录、图片、资料上传或本人创建的导入批次。已软删除的业务记录也属于历史，不会随成员删除。已有记录应使用匿名化；已匿名化成员的后台隐私任务必须先完成，避免丢失清理依据。

允许删除时，在现有数据库事务内移除成员行、凭据、全部会话、学号索引、角色关联及已完成隐私任务，正确减少角色人数；同步清除其他导入批次中该成员的 UID/身份快照，保留批次进度和其他成员行；清除可关联到该 UID 的登录 IP/设备元数据。保留最小审计骨架，以及操作者、时间、目标 UID 和 `members.purge` 操作记录，不保存密码或确认输入。已导出的文件、备份和未关联到 UID 的未知账号登录失败记录不在此操作范围。

学号释放后可重新创建账号，但新账号拥有新的 UID，不能恢复旧会话或旧身份。此功能不提供批量清空或级联删除帖子/活动。数据库触发器检查所有现有及未来指向 users 的外键，额外检查未建外键的 JSON 业务关联；关联检查、清理、角色计数和审计一起提交，失败全部回滚。

## 部署顺序

1. 已完成013和前置迁移的环境，在 CloudBase PostgreSQL SQL 编辑器执行 `cloudbase/sql/014-member-purge.sql`。使用事务、版本记录和现有角色，不创建数据库角色，可重复执行。安装仅新增权限、触发器及能力标记，**不会执行任何成员删除或修改密码/既有角色分配**。
2. 可执行 `014-member-purge-verify.sql` 只读核对：版本/权限/标记存在，member_purge 触发器启用，角色计数一致，浏览器数据库角色无执行权限。
3. 替换原云函数为最新 `deployment-packages/electronicclub-api.zip`，核对旁边 SHA256。入口 `index.main`，保留原环境变量，无新增密钥或服务配置。
4. EdgeOne 部署最新 main 前端。现有 `/admin/*` 回退覆盖该界面。超级管理员打开已软删除成员即可操作；授权其他角色时在权限界面勾选「彻底删除成员（不可恢复）」并保留成员查询权限。

新增 POST `/api/members/:uid/purge`，JSON `{ "confirmUid": "与路径相同的成员UUID" }`。沿用登录 Cookie、CSRF、数据库 RBAC 和事务控制；前端隐藏按钮不是授权依据。未安装014时返回明确的数据库升级提示，不尝试直接删除。关联/状态冲突返回409，越权返回403，缺少登录返回401。

## 回滚

优先撤销非超级管理员的 `members.purge` 授权，回退前端/函数并保留014。保留触发器不会影响既有软删除、恢复和匿名化流程。确需停用能力，可由受控SQL将 `system` 中 `member_purge` 标记移除，新函数会拒绝执行；不要为回滚删除业务数据或重新初始化成员。已经彻底删除的账号不可通过「恢复成员」找回，若误删只能按备份恢复流程单独评估，不能用整库覆盖在线数据。

本交付不代表已在生产库执行迁移或删除真实成员；验证仅使用本地专用测试账号与数据库。
