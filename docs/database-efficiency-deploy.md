# 数据库访问优化部署

此更新优化现有 CloudBase PostgreSQL HTTPS RPC 和 Linux PostgreSQL 共用的业务代码。不增加数据库、认证系统、付费缓存服务或定时任务，不清空表、不修改账号和密码。属于现有访问路径的性能修正，没有 SQL 或部署架构变更，不刷新稳定 Linux/运维归档。

## 当前云环境执行顺序

1. **SQL：无需执行。** 已有 015 及之前迁移保持原样；不要重新初始化或补跑旧安装脚本。
2. **CloudBase：** 下载 [electronicclub-api.zip](../deployment-packages/electronicclub-api.zip) 和 [SHA256](../deployment-packages/electronicclub-api.zip.sha256)，核对后替换现有 `electronicclub-api` 的代码。ZIP 根目录直接包含 `index.js`、`package.json`、`package-lock.json` 和全部 `node_modules` 运行依赖。入口保留 `index.main`，原运行时、HTTP 网关和全部环境变量保留。
3. **EdgeOne：** 重新部署最新 main，包含根目录 `edge-functions`。构建命令和输出目录保持原值；不要只上传 dist。前端这次合并并发的 `/auth/me` 请求，继续同源 `/api` 和 Cookie 恢复验证。
4. **环境变量：无需新增或修改。** CloudBase 中的数据库、Cookie、Origin、七牛配置，以及两端已有 `ECLUB_PROXY_SECRET` 都沿用。缓存默认自动启用，不用配置额外密钥或服务。

本地构建和推送代码不会自动上传 CloudBase ZIP。生产 SQL、函数发布和真实手机操作没有在本地验证中执行。

## 行为与一致性

- 活动、新闻的公开列表和公开详情，以及公开资料列表，在**单个温热后端实例**内缓存 60 秒。同条件并发读取共用一次加载。缓存最多 64 项、4MiB，单项最多 1MiB，超过限制直接查询；失败不缓存，不持久化。
- 任意业务写请求开始及结束时清理本实例缓存；旧的在途查询不会把过期内容重新写入缓存。不同实例之间没有共享缓存失效通知，因此另一实例、维护脚本或 SQL 编辑器的修改最长约 60 秒后可见。这也适用于公开内容的撤回，不能当作即时全局失效。
- 论坛、定时公告弹窗、图片、下载地址、登录、成员资料、权限和后台数据不进入上述响应缓存。定时公告仍按当前时间选择，稳定的选择结果不再反复改写 `popup_state`。
- 会话有效期、账号状态、版本和数据库角色权限每次请求都检查。闲置续期的写入最多每分钟一次；闲置超时由原来的逐次滑动 30 分钟变为约 29–30 分钟，绝对过期时间不变，不会延长会话。封禁、重置密码、角色调整仍即时检查生效。
- 普通读取不再改写全局 `system/control`，真正的业务写入保留全局安全变更控制、最后超级管理员保护和事务审计。
- 原生 PostgreSQL 在同一事务内合并相同行的读取，并在写入后清理可能受触发器影响的快照。HTTPS RPC 保留行快照的 `ec_commit` 校验和冲突重试；只有完全没有行读取和写入的事务省略空提交，不以省查询为由跳过权限一致性检查。
- HTTP 响应仍为 `no-store`，没有把 Cookie、权限、成员信息或带签名的下载地址放入浏览器/CDN 共享缓存。

## 核对与回滚

更新函数后，请求网站 `/api/health`。响应头应包含 `X-EClub-Data-Revision: db-efficiency-v1`；原 `X-EClub-Backend-Revision: gateway-body-v5` 和边缘版本头继续保留。健康检查不连接数据库，可以用于核对包版本，不应当作数据库连通性验收。

正常使用时核对登录/刷新/退出、调整角色后的权限、活动发布编辑、报名审核签到、公告切换、论坛审核和资料下载。无需对生产环境做循环压测。

回滚只需恢复更新前云函数版本及对应前端，无 SQL 回滚、密码重置或数据恢复操作。回滚时缓存随进程替换清空。

## 资源点说明

CloudBase 体验套餐按月度套餐周期补充资源点，控制台显示的周期可能不从每月 1 日开始。用户截图的当前周期为 2026-11-02 00:00:00 至 2026-12-02 23:59:59；下周期额度以控制台显示为准。更新代码不会恢复本周期已消耗的额度。

截图显示共享 PostgreSQL 按有使用的 5 分钟时段计量。减少查询、重复写入及锁竞争有助于降低负载，但短时进程缓存不能保证数据库跨时段休眠：冷启动、多实例、后台操作和正常访问都会访问数据库。不能把查询减少比例直接当作资源点节省比例，也不承诺 3000 点能支撑整月运营。

本地成本回归包含同条件 20 个并发公开列表请求只执行 1 次底层业务事务、缓存失效/过期/容量/在途竞态、读取不改写全局控制记录、分钟级续期、禁用即时生效、实时公告和 HTTPS RPC 无写入时仍验证冲突。完整构建、真实 PostgreSQL/HTTPS RPC 业务回归和生产依赖审计结果见 [当前交付记录](../deployment-packages/README.md)。所有数据库测试连接隔离的本地数据库，没有压测生产 CloudBase。
